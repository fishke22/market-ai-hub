【開工與跨對話交接】
在 Codex 本機直接用原生專案與 terminal 工具；在 ChatGPT 網頁版優先使用 Remote Desktop Commander：列設備→確認實際 repository 根目錄與 remote→讀 AGENTS.md→檢查並執行 scripts/agent_bootstrap.ps1→讀 docs/development/AGENT_HANDOFF.md、project-status.md 與本階段 contract。不假設本機一定在 D 槽，也不將 ChatGPT sandbox 當使用者電腦。
記錄實際時間、branch、HEAD、remote main、dirty/untracked、build_id。工作樹可能由另一個 agent 施工；不 reset/clean/stash、不搶改、不覆蓋既有變更。遇到重疊先確認工作所有權；繼續能獨立完成的查核。
不要重建已完成階段；但新的反例與失敗測試可以重開局部 correctness 修補。以一個可驗收工作包為單位：讀相關呼叫鏈→最小修補→針對性反例測試→必要整合驗證→更新交接→發布驗證。不要在同一棒偷偷加整套未核准架構。
使用者途中補充通常是修正或補充，不是停止指令。工具可用時繼續已授權工作，不只給計畫。

【可信度不可混淆】
ENGINE PASS ≠ DATA READY ≠ CALIBRATED ≠ PREDICTIVE EVIDENCE ≠ TRADING EDGE。
支援 API ≠ 帳號 entitlement；login accepted ≠ subscription accepted ≠ matching live callback ≠ 目前每欄行情仍新鮮。
現貨、期貨、連續序列、實際合約、proxy、settlement、bar close 分開；因子有 venue/session/contract/roll/時間與來源證據。
特徵 available_at ≤ cutoff ≤ forecast_origin；結果在 horizon 到期後獨立封存。禁止 random time split、未來資訊、修訂後總經回填成當時已知、用 final OOS 調參。合成測試資料永不算市場績效。
CLASS_SCORE 不是機率；校準狀態必須解析有效證據，不能憑字串或任意 evidence ID。不能從幾個分位數捏造完整分布、touch 或 first-passage 機率。CALIBRATED 必須按標的、horizon、事件家族、模型版本與有效期間分別驗收。

【設計與白話解讀】
沿用既有 Price Map + Probability Map：中心、Buy/Neutral/Profit Zone、Breakout/Breakdown、Model Failure；分開 terminal、touch、先觸及上/下界及皆未觸及。檢查非對稱、厚尾、多峰、regime，但沒有足夠證據就說未知。
Zone 是版本化研究定義，不是自動買賣訊號。Reward/Risk 與淨期望值由程式依事件、成本、滑價及失效条件計算；LLM 不自編機率、價格或最佳策略。
白話回答依序交代：商品/合約與時點→資料是否新鮮→已知位置與狀態→已驗證的預測與限制→風險/失效條件→觀察或研究情境。資料不足時明講「目前不能可靠比較哪邊機率較高」。如何操作以軟體使用及研究情境為主；既有 RESEARCH_ONLY、NO ORDER 與個人化交易指令限制不因新功能消失。
